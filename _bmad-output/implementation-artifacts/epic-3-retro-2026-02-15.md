## Key Insights

### 1. Epic 4 Pattern Repeated Exactly
> We identified the "no testing before done" problem in Epic 4 retrospective, committed to fix it, then repeated the exact same mistake in Epic 3. This is a systemic issue, not a one-time error.

**Evidence:**
- Epic 4: 0/8 stories worked without fixes
- Epic 3: 0/7 stories worked without fixes
- Both epics: All issues found during first manual test
- Both epics: API contract mismatches between frontend/backend

**Lesson:** Action items from retrospectives must be enforced, not just documented.

### 2. API Contract Mismatches Are Predictable
> When frontend and backend are developed separately without a shared contract specification, integration failures are guaranteed, not possible.

**Evidence:**
- Frontend expected: `{success: true, data: {computed: "..."}}`
- Backend returned: `"..."` (raw value)
- Multiple iterations needed to align formats
- No documentation of expected contract

**Lesson:** API contracts must be documented and validated before implementation.

### 3. Unit Tests Don't Catch Integration Issues
> 42 passing Go unit tests gave false confidence. Integration between frontend and backend was completely broken despite all unit tests passing.

**Evidence:**
- All Go unit tests passed
- All Playwright web mode tests passed (32 tests)
- Electron app completely broken (editing didn't work)
- Different code paths: web mode uses HTTP, Electron uses HTTP + IPC

**Lesson:** Need dedicated integration tests that exercise the full stack.
